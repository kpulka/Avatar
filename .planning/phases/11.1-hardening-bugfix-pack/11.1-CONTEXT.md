## Implementation Decisions

### Threat model for the embed bridge (why these fixes, not others)

The widget is served from a GitHub Pages origin. Attack paths that are REAL today:

1. **Opener attack (HIGH).** `evil.example` calls `window.open('https://<owner>.github.io/Avatar/')`.
   `document.referrer` = evil origin → `embed-bridge.ts:48-57` adds it to the allowlist → evil can
   `postMessage({type:'avatar:set_agent', agentId:'agent_evil'})` then `{type:'avatar:connect'}`.
   If the visitor ever granted microphone permission to the owner's origin (persistent grant), the mic
   starts **without a click** and the visitor's voice streams to the attacker's ElevenLabs agent
   (attacker reads transcripts in their own dashboard). `set_agent` persists to localStorage, so the
   hijack survives reloads.
2. **Persistent agent hijack via iframe (MEDIUM).** Same `set_agent` path from any embedder trusted via
   referrer or `?parent_origin=`.
3. **Wildcard in production (MEDIUM).** `?allow_any_origin=1` (`:44-45`, `:117`) disables inbound checks
   and emits transcripts with targetOrigin `'*'`. Any page can enable it by choosing the iframe URL.

NOT a real threat (do not over-engineer): an iframe embedder setting `?parent_origin=` to itself. In an
iframe, mic permission is delegated to the **top-level** origin, so the embedder already needs the user to
grant mic to *it*. With `set_agent` removed and `event.source === window.parent` enforced, the embedder can
only drive the owner's agent for its own visitors — acceptable for a public demo agent.

### Decisions (locked)

- **D-1 Source check:** a message is trusted only if `event.source === window.parent` AND the widget is
  actually framed (`window.parent !== window`). Top-level (not framed) → bridge ignores all inbound messages.
  This kills the opener attack regardless of origin lists.
- **D-2 Referrer:** `document.referrer` is never used for trust. Delete it.
- **D-3 Origin allowlist:** keep `options.allowedOrigins` + `?parent_origin=`; if both empty → same-origin only.
  An empty/undefined `event.origin` is NEVER trusted (today `isOriginTrusted` returns true for `!origin`, `:112`).
- **D-4 `avatar:set_agent`:** removed from the protocol entirely (callback type, dispatch case, controller wiring).
  agentId sources are only: URL `?agent_id=` > Settings (store) > default. (Owner decision D2 in refactoring.md R9.)
- **D-5 Wildcard:** `allow_any_origin` honored only when `devMode` is true. `devMode` is an
  `EmbedBridgeOptions` field defaulting to `import.meta.env.DEV` (testable; tests pass it explicitly).
- **D-6 Outbound targetOrigin:** after the first trusted inbound message, reply to that exact
  `event.origin`. Before that, post once per allowlisted origin (the browser silently drops mismatched
  targets, so nothing leaks), or to same-origin when the list is empty. Never `'*'` outside devMode.
- **D-7 `avatar:say`:** text trimmed and capped at `MAX_SAY_CHARS = 500` (longer → truncated + console.warn).
- **D-8 Dead embed config:** delete `theme`, `autostart`, `modelUrl` from `EmbedConfig`/`parseConfigFromUrl`
  (no consumer; `model_url` would become a remote-asset injection vector the day someone wires it).
- **D-9 agentId single source:** `SettingsStore` (`studio.agentId`) is the only persisted source. The
  legacy localStorage key `elevenlabs_agent_id` is no longer written by anyone (migration may still READ it once).
- **D-10 sampleRate travels with the chunk:** `onAudioChunk` gets an explicit `sampleRate` argument; the
  controller stops asking `getOutputSampleRate()` at emit time.
- **D-11 Avatar dispose:** `Scene.clearAvatar()` disposes geometries, materials, material textures and
  skeletons of the removed subtree; never disposes `scene.environment` / `material.envMap`.
- **D-12 Compare lanes:** each lane sets the animation mode it needs before feeding the face controller and
  `run()` restores the user's mode at the end; `run()` returns `false` on failure (not `true`).
