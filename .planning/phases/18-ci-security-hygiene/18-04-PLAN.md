# Plan 18-04: ESLint + Prettier (layering rule from the 14-02 contract)

## Goal

Editor-level feedback for the rules that already gate CI: ESLint with typescript-eslint
plus a layering rule that imports `tests/layering-rules.ts` as its single source of
truth, and Prettier with a config matching the existing style — adopted with clearly
labeled commits so blame stays readable.

## Requirements

QUAL-05 (lint/format).

## Files

- `eslint.config.js` — NEW (flat config)
- `.prettierrc.json` — NEW
- `package.json` — devDependencies + scripts
- `.github/workflows/ci.yml` — add `npm run lint` + `npm run format:check` steps
- source/test files — only where rules flag

## Tasks

1. Install devDeps: `eslint`, `typescript-eslint`, `eslint-plugin-import` (for the
   boundary rule), `prettier`. Scripts: `"lint": "eslint src tests"`,
   `"format": "prettier --write .", "format:check": "prettier --check ."`.
2. `eslint.config.js` (flat):
   - base: typescript-eslint **recommended-type-checked** (dial down to recommended if
     the strict variant produces noise beyond this plan's budget — record the choice);
     project service from `tsconfig.test.json` (14-01) so tests type-check in lint too;
   - **layering rule**: `import/no-restricted-paths` (or a small custom rule) configured
     **from `tests/layering-rules.ts` imports** — the file must be importable from a
     plain Node context (flat configs are ESM; if the test file's vitest imports block
     it, extract the data to `layering-rules.json` imported by both — single source
     preserved);
   - sensible additions: `no-console` as warn (console is the telemetry channel here —
     keep as warning, not error), `eqeqeq`, `prefer-const`.
3. `.prettierrc.json` matching current style: `printWidth: 100, singleQuote: true,
   trailingComma: 'all'` — verify by running `prettier --check` on 5 untouched files
   first; if the real style differs, match reality, not aspiration.
4. **Commit A** — `chore(lint): ESLint + Prettier config; fix violations`: run lint,
   fix every error (warnings allowed only with inline reasons), zero errors on src+tests.
5. **Commit B** — `style: prettier one-shot format`: the format sweep, nothing else in
   the diff (verify: `git diff --stat` touches formatting only; `npm test` green both
   before and after).
6. CI: add lint + format:check steps after typecheck.
7. Record in SUMMARY: violation classes found (they're a free architecture audit —
   e.g. unexpected `any` survivors, unused imports) and their dispositions.

## Acceptance criteria

- [ ] `npm run lint` + `npm run format:check` green on src+tests
- [ ] Layering ESLint rule reads the same data as `tests/layering.test.ts` (single source
      — SUMMARY shows the import both ways)
- [ ] Two labeled commits (violations-fix / one-shot format); `npm test` green across both
- [ ] CI runs lint + format:check; badge still green

## Test/verification strategy

CI is the standing verification; the negative check (temporarily add a forbidden import
locally → lint fails) is done once in SUMMARY as proof the rule bites.

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| typescript-eslint strict noise exceeds budget | Recommended fallback documented; the win is the layering rule + baseline, not maximal strictness |
| One-shot format sweep huge | printWidth/style matched to reality first (task 3); if sweep still > ~300 files, split per-directory commits |
| Rule data duplicated (test vs config) | Single-source requirement in acceptance; if extraction to JSON is needed, BOTH the test and config import the JSON |
