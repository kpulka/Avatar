# Plan 18-01: Secrets scan + SECURITY.md (priority 1 — nothing ships before this)

## Goal

Prove the public repo (including its full history) contains zero credentials, publish a
security policy, and close the .env gap — so the rest of the phase builds on a clean
foundation.

## Requirements

QUAL-01 (secrets & security).

## Files

- `SECURITY.md` — NEW
- `.gitignore` — add `.env*` if absent (verify first)

## Tasks

1. **HEAD scan**: grep the working tree for credential shapes — `xi-api-key`,
   `xi_api_key`, `sk-`, `api[_-]?key\s*[:=]\s*['"][A-Za-z0-9]`, `Bearer `, long
   base64/hex literals in src/config; also list any `*.env*` files present (there should
   be none).
2. **History scan** (the one that matters): run gitleaks over the whole repo history
   (`gitleaks detect --source . --no-git=false` via `npx`/binary, or equivalent —
   if tooling is unavailable, `git log -p | grep -nE '<patterns>'` with the same
   patterns over full diffs is the documented fallback). Record: tool, version, findings
   count.
3. **Disposition per finding** (if any): rotate the credential FIRST (owner action),
   then decide — for live secrets, history rewrite is a breaking, owner-level decision;
   for dead/rotated ones, removal from HEAD + a SECURITY.md note suffices.
4. **Verify the design intent holds**: `xi-api-key` appears in docs (as the thing that
   must never reach the client — docs/2, README) but in zero client code paths
   (`grep -rn "xi-api-key" src/` → only the negative-policy comment, if any).
   Re-confirm the public-`agent_id` usage sites (settings UI, embed-bridge allowlist)
   match the "public by design" policy in 18-CONTEXT §1.3.
5. `SECURITY.md`: supported version (v1.x), scope (client app + repo; the ElevenLabs
   agent config is out of repo scope), disclosure contact (owner's preferred channel —
   GitHub private vulnerability reporting), the public-agent-id policy (public agents
   are by-design public; quota abuse contact), and a "what we never store" line (API
   keys server-side only, signed-URL design).
6. `.gitignore` audit for secrets-adjacent entries: `.env`, `.env.*`, `*.pem`,
   `*.key` — add what's missing.
7. Commit: `chore(security): full-history secrets scan clean; SECURITY.md; .env ignore`.

## Acceptance criteria

- [ ] Scan record in SUMMARY: tool + version + scope (HEAD + full history) + findings
- [ ] Zero live findings (or: rotated + dispositioned, documented)
- [ ] `SECURITY.md` published with disclosure channel + public-agent-id policy
- [ ] `.gitignore` covers `.env*`; no `*.env` file is tracked
- [ ] `grep -rn "xi-api-key" src/` → policy comments only

## Test/verification strategy

The scan IS the test; re-run in 18-VERIFICATION §1. If gitleaks is added to CI later
(optional backlog), its config comes from this plan's pattern list.

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| History rewrite needed (live secret found) | Owner decision gate; rotate first, rewrite only with explicit consent; document the breaking change |
| Scan tool unavailable offline | Documented grep-over-`git log -p` fallback with the same patterns (worse signal/noise, still a scan) |
| `.env` created by a future contributor | .gitignore + SECURITY.md statement; CI never needs env (public repo, no secrets to inject) |
