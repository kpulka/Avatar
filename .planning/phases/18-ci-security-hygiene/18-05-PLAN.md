# Plan 18-05: GitHub Pages demo (demo mode, no live conversation by default)

## Goal

Deploy a static demo where a stranger can SEE the avatar talk within seconds of clicking
the README link — without exposing the owner's ElevenLabs quota. Demo mode = avatar +
demo speech + synthetic A2F frames + bring-your-own-agent_id field; conversation with
the owner's live agent only if the owner explicitly opted in (D4 ask, bundled at phase
start).

## Requirements

QUAL-06 (Pages demo).

## Files

- `vite.config.ts` — `base` from env (`BASE_PATH`, default `/`)
- demo-mode wiring — additive: a `?demo=1`/build-flag that (a) starts the app with the
  demo utterance ready, (b) shows the agent_id input in Settings with "bring your own"
  copy, (c) hides owner-internal panels if any are marked demo-hidden
- `.github/workflows/deploy-pages.yml` — NEW (build with `BASE_PATH=/Avatar/`, deploy to
  Pages on push to main)
- `README.md` — demo link slot fill

## Tasks

1. **Owner decision recorded** (D4): default demo (no live conversation) vs live agent
   with accepted quota cost. The rest of this plan assumes the default; a live-agent
   variant only changes the copy + a demo agent_id in the demo build env (documented
   diff in SUMMARY if chosen).
2. Demo-mode design (keep it small — this is a showcase, not a product):
   - `?demo=1` URL flag → `sessionStorage` persistence → the app boots to the user layer
     with a visible "Play demo" affordance — **reuse the 11.2 SHOW-01 "Listen" button**
     (recorded TTS clip + real alignment + captions), not the old tone-based demo speech
     (amended 2026-11-19 — see 11.1/11.2);
   - Settings shows the agent_id field with bring-your-own copy; pasting one enables
     the full conversation loop exactly as in dev (zero server involvement). The value is
     stored in SettingsStore (11.1-02; `?agent_id=` URL wins), never via postMessage
     (`avatar:set_agent` was removed in 11.1-01). The demo must not rely on
     `?allow_any_origin=1` (dev-only since 11.1-01);
   - demo banner: "Demo build — for the full developer setup see the README".
   - No feature flags framework; one boolean through the existing settings/store.
3. Build wiring: `base: process.env.BASE_PATH ?? '/'` in vite.config.ts (CI main build
   unaffected); verify asset URLs resolve under `/Avatar/` subpath.
4. `.github/workflows/deploy-pages.yml`: on push to main (after CI passes —
   `workflow_run` or a job `needs`), checkout → build with `BASE_PATH=/Avatar/` →
   deploy via `actions/deploy-pages`. First deploy: verify the real avatar GLB (committed in
   11.2 SHOW-09; owner accepted license responsibility 2026-11-19; ~11.9 MB or less if compressed)
   loads within the Pages size limits and the lazy CMU chunk (or 17-01 pruned lexicon,
   whichever exists) still lazy-loads.
5. Cold-demo check (the 13-02 checklist, deployed): open the Pages URL in a clean
   browser profile — real MetaPerson avatar renders (not the fallback mannequin), the Listen demo plays with captions, barge-in via the interrupt
   button mid-utterance, studio reachable, no console errors.
6. Fill the README demo slot (13-01's exact line); language gate green.
7. Commit: `feat(demo): demo-mode build + GitHub Pages deploy; README demo link`.

## Acceptance criteria

- [ ] Pages URL live; cold-profile check green (render, demo speech, interrupt, studio)
- [ ] No owner agent_id in the demo build (unless D4 live-variant chosen — recorded)
- [ ] Assets resolve under `/Avatar/` base; GLB + lazy chunk load
- [ ] README demo slot filled; deploy workflow green on main

## Test/verification strategy

The deployed cold-profile check IS the test (recorded in SUMMARY with the checklist
results); CI keeps the main build honest; the demo build diff (base path + flag) is
covered by the existing suite running on the same code.

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| Quota exposure via bring-your-own field abuse | BYO field uses the *visitor's* agent_id (their quota, their choice); no owner credential ships |
| Pages cold start slow with 11.9 MB GLB | GLB is cached after first load; measure TTI in the cold check; if > ~10 s, note it + backlog a compressed LOD variant (explicitly out of v1.1 scope) |
| Demo drifts from dev behavior | Same code, one flag; the flag's paths get a smoke assertion in the existing test suite (settings round-trip with demo=true) |
