# Plan 18-03: CI workflow + badge

## Goal

Every push and PR gets a green (or honestly red) check: `npm ci` → typecheck → test →
build, on a clean Linux checkout — turning "204 tests, strict TS" from claims into
publicly verifiable facts, with the badge in the README's waiting slot.

## Requirements

QUAL-02 (CI + badge).

## Files

- `.github/workflows/ci.yml` — NEW
- `README.md` — badge slot fill

## Tasks

1. Write the workflow (boring by design, 18-CONTEXT D3):

   ```yaml
   name: CI
   on:
     push: { branches: [main] }
     pull_request:
   jobs:
     verify:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4
         - uses: actions/setup-node@v4
           with: { node-version: 22, cache: npm }
         - run: npm ci
         - run: npm run typecheck   # requires 14-01 landed; else TODO(14-01) comment + skip
         - run: npm test
         - run: npm run build
         - uses: actions/upload-artifact@v4
           with: { name: dist, path: dist, retention-days: 7 }
   ```

2. **Path-separator pre-check** (R-3): the fs-based gates (`tests/language.test.ts`,
   `tests/layering.test.ts`) must pass on Linux. Run `npm test` locally with normalized
   paths first; if a gate hardcodes `\`, fix the gate (path.join/normalize) in this plan
   — that's a portability bug worth fixing regardless.
3. Push to a branch, open a draft PR, watch the run: green on the first try is the goal;
   a red first run is a *finding* (fix, document in SUMMARY — what differed between
   Windows dev box and ubuntu runner).
4. Fill the README badge slot with the exact URL from 13-01's placeholder comment:
   `[![CI](https://github.com/kpulka/Avatar/actions/workflows/ci.yml/badge.svg)](…/ci.yml)`.
5. Confirm total runtime ≤ ~3 min (record actual in SUMMARY; tune cache/artifact if not).
6. Commit: `ci: verify pipeline (typecheck+test+build) on push/PR`.

## Acceptance criteria

- [ ] First PR run green (or red→fixed→green with the divergence documented)
- [ ] fs-based gates pass on ubuntu (portability fixes in-plan if needed)
- [ ] Badge live in README; workflow runtime recorded ≤ ~3 min
- [ ] `npm ci` used (lockfile-exact — never `npm install` in CI)

## Test/verification strategy

The workflow run IS the test — its public status page is the evidence; 18-VERIFICATION §1
links the first green run.

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| Typecheck step dead if 14-01 lags | Dependency declared; fallback ships the step commented with TODO(14-01) and a follow-up (never a silently absent step — README would badge a lie) |
| Gates red on Linux (separators, CRLF) | Task 2 pre-check + in-plan gate fixes (portability wins regardless of CI) |
| Runtime creep | npm cache + no matrix + 7-day artifact retention; measure, don't guess |
