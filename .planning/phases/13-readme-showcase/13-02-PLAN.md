# Plan 13-02: Cold-clone quickstart verification

## Goal

Prove the README's quickstart empirically: run the printed commands from a fresh clone
(no node_modules, no prior state) and record what actually happens — so the README's most
important promise ("four commands and you see a talking avatar") is tested, not asserted.

## Requirements

READ-03 (quickstart reproducibility + troubleshooting).

## Files

- `README.md` — only if reality differs from the draft (amend, don't restructure)

## Tasks

1. Cold clone: `git clone <repo> L:/tmp/opencode/avatar-coldstart` (or a fresh local
   clone of the current branch); verify NO `node_modules`, NO build artifacts inside.
2. `npm install` — record duration and any warnings (peer deps, engines).
3. `npm run dev` — record: startup time, the exact local URL (must be
   `http://localhost:5310` per `strictPort`), and any first-run console output worth
   knowing.
4. Browser check (dev machine, headless acceptable if a screenshot can be captured):
   - Avatar renders without any configuration (loader → `avatar:loaded` → mesh visible).
   - Animation panel demo speech plays with visible lip movement.
   - Studio toggle (`?studio=1`) opens the six panels.
   - Conversation without an agent_id fails with a *readable* error, not a crash —
     the README's troubleshooting block must match the actual message wording.
5. `npm test` + `npm run build` + `npm run typecheck` in the cold clone — all green
   (this also validates QUAL-08's "fresh clone passes all gates with only Node.js").
6. Amend README ONLY where reality differed (command, URL, error wording, Node version
   floor). Record deltas in SUMMARY. If everything matched, SUMMARY says so explicitly —
   that's the deliverable: a verified claim, not a lucky one.

## Acceptance criteria

- [ ] Cold-clone run recorded in SUMMARY (commands, timings, outputs)
- [ ] All four checks of task 4 pass; conversation-without-agent error wording matches
      README's troubleshooting block (or README amended)
- [ ] Full gate set green in the cold clone (test/build/typecheck)
- [ ] README deltas committed (or "no deltas needed" recorded)

## Test/verification strategy

The run IS the verification. 13-VERIFICATION §1 references the SUMMARY record;
18-05 (Pages demo) reuses this checklist for the deployed build.

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| Dev-machine state hides a real setup gap (global caches) | The clone directory is fresh; npm cache is fine to keep (it's standard), but no `--force`, no global installs |
| Port 5310 occupied on the machine by the dev copy | Kill the dev server first or run the cold clone in a container/VM; `strictPort` failing IS a finding to document (troubleshooting already covers it) |
| Conversation check needs an agent_id | Out of scope for the cold run by design — the README's honest claim is "visuals zero-setup, conversation needs agent_id"; only the *error path* is verified here |
