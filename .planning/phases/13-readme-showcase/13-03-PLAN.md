# Plan 13-03: Visual assets — screenshots, GIF, social preview (gated on Phase 15)

## Goal

Produce the README's visual layer — the thing a 30-second reviewer actually judges — now
that Phase 15 has made both themes presentable, and swap the README slots for real
assets. This plan is **gated**: it must not execute before Phase 15 lands (broken light
theme would be showcased, not fixed).

## Requirements

READ-05 (visual assets, budgets, alt text).

## Files

- `assets/` — NEW directory at repo root
- `README.md` — slot swap only (no text restructuring)

## Tasks

1. **Preconditions check** (stop if unmet): Phase 15 landed (light theme on tokens);
   `npm run dev` clean; no console errors during a session.
2. Capture script (human + agent assisted — the operator drives the app, the plan
   specifies the exact moments):
   - **Hero (dark theme)**: avatar mid-speech, mouth clearly articulated, studio hidden,
     clean user layer. 16:9, ~2560×1440 → optimize to ≤ 300 kB PNG.
   - **Talk + barge-in GIF**: ≤ 6 s loop — start a turn, let 2–3 words play, interrupt
     visibly (mouth snaps to relax). ≤ 3 MB, 30 fps, 1280×720 max. This single asset
     demonstrates the product's hardest feature.
   - **Light theme shot**: same framing as hero, after verifying 15's token system
     renders it correctly.
   - **Studio shot** (optional, if budget allows): `?studio=1` with the six panels —
     signals engineering depth.
3. **Social preview card** (1200×630): avatar close-up + wordmark text "Avatar —
   real-time conversational 3D avatar"; high contrast for dark-mode GitHub. This file
   also feeds 18-06's repo-metadata task.
4. Place files under `assets/`; swap the README slots (`<!-- 13-03 … -->`) for image
   references with meaningful alt text (READ-05); verify the language gate still passes
   (alt text is English, ASCII).
5. Verify rendered README on github.com (or a local GFM preview): images load, no
   layout shift beyond the slot size, GIF autoplays muted.
6. Commit: `docs(readme): visual assets — hero, barge-in GIF, light theme, social card`.

## Acceptance criteria

- [ ] All 3 mandatory assets + social card in `assets/`, within budgets (hero ≤ 300 kB,
      GIF ≤ 3 MB, card ≤ 500 kB)
- [ ] README slots replaced; alt text present; language gate green
- [ ] GIF demonstrably shows speech + interruption (review in UAT §3)
- [ ] Social preview handed to 18-06 (path recorded in SUMMARY)

## Test/verification strategy

Manual review is inherent (it's a visual deliverable); budgets checked by file size;
README rendering verified on github.com. 13-VERIFICATION §3 signs off the visual pass.

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| GIF too heavy after encoding | Hard budget: drop to 720p/24 fps or trim to 4 s; if still > 3 MB, ship hero-only and file a follow-up for an external capture link |
| Capture reveals a 15 leftover (e.g. one un-tokenized color) | Stop; file the bug to Phase 15's owner; re-shoot after the fix — do not ship a screenshot of a known bug |
| Social preview text unreadable at small sizes | Test at 560 px width (GitHub card render) before committing |
