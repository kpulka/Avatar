# Plan 15-05: States, error recovery, first-run honesty, feedback hygiene & compare UX

## Goal

Make every state in the coverage matrix (15-CONTEXT §4.2) honest and recoverable: connection
errors get a retry banner (consumes the orphaned `voice:error`), mic-denied stops faking
"listening", avatar double-failure surfaces in the loader, captions clamp + apply
corrections, destructive resets confirm, toasts stop spamming, and the compare flow gets its
A/B chips, cancel button and blind-safe reveal. This is the plan with the cross-seams into
`features/` and `audio/` (each flagged in 15-CONTEXT §5.1, §7.3 for Phase 14 review).

## Requirements

UIX-05, UIX-06.

## Files

See frontmatter. New tests: `tests/compare-ui.test.ts`, `tests/states-recovery.test.ts`.

## Tasks

1. **Connection error banner (findings A3 + UI-SPEC §3.6):** in `container.ts`, subscribe
   `voice:error` → render a `.conn-error` banner (fixed, top-center below status,
   `role="alert"`) with slot `errors.connection.title`/`errors.connection.body` + a
   "Spróbuj ponownie" button calling `services.conversation.start()`; banner hides on
   successful `voice:state !== 'idle'`. Keep the toast (redundant channels are fine).
2. **Mic-denied honesty (finding A2) — cross-seam in `speech-backend.ts`:** in `start()`,
   rethrow after the catch (or resolve a typed result) so `ConversationController.toggle()`
   can catch it: on `err.name === 'NotAllowedError'` emit `voice:state 'idle'` +
   `voice:error` with slot `errors.micDenied`; on other mic errors slot
   `errors.micFailed`. Never set `isRunning=true` + `'listening'` when the mic didn't open
   (invert the current order at speech-backend.ts:160-172: mic first, then connect; or
   verify `micCapture.isActive` before declaring listening).
3. **Avatar double-failure (finding S1) — cross-seam in `scene-controller.ts`:** in
   `loadDefaultAvatar()`'s inner catch, emit a new `avatar:error` (add to `AppEvents` in
   `app-types.ts` with payload `{ message: string }`) instead of only `console.error`;
   `container.ts` subscribes → `loaderUi.error(slot)` with retry hook calling
   `services.scene.loadDemo()` (demo avatar is a synchronous generator — the known-good
   fallback). Remove the old `console.error`-only path.
4. **Captions clamp + fade (finding S3):** `style.css`: `.transcript-line .transcript-text`
   gets `display: -webkit-box; -webkit-line-clamp: 3; -webkit-box-orient: vertical;
   overflow: hidden` per line-box; `.transcript-box` max-width stays 720px, add
   `max-height: 7.2rem; overflow: hidden` + `mask-image: linear-gradient(transparent 0,
   black 12%)` so older content fades (11-UI-SPEC "wrap to 3 lines with fade of older
   lines" — finally implemented).
5. **Interrupted-turn correction (finding S4) — cross-seam:** wire

   `.caption-flash` CSS class (background pulse 600 ms, respects reduced-motion) applied by
   `captions.ts` on `speech:interruption` for the agent line — the visible "interrupted"
   cue.
6. **Toast de-spam (finding S6) — cross-seam in `conversation-controller.ts`:** delete

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| speech-backend start-order inversion breaks autoplay unlock semantics | Keep `audioEngine.unlock()` first; only gate the "listening" declaration + isRunning on mic success; test with mocked mic paths |
| `avatar:error` event addition ripples into embed-bridge/telemetry consumers | Additive event, no consumer breaks (typed bus); container is the only new subscriber |
| De-spam removes feedback users relied on | Mute state still visible via label + aria-pressed; PoC/stress toasts untouched; owner UAT signs off |
| A2F probe false-negatives on cold wrapper | Timeout 1500 ms only disables with a tooltip reason; Compare still attempted on click (probe is advisory) |
| Cross-seams drift before Phase 14 review | Each seam is ≤10 lines and listed in 15-CONTEXT §7.3; 15-VERIFICATION §6 restates them for the orchestrator |
