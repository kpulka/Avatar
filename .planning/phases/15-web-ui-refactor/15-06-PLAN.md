# Plan 15-06: Studio discoverability — Settings toggle + `?studio=1` documented backdoor

## Goal

Resolve the review-A1 open item ("document `?studio=1`") with a product decision instead of
docs-only (15-CONTEXT §5.2): expose a discreet, lock-respecting "Studio mode" switch inside
the user Settings modal, keep the URL backdoor + shortcut working, and make the first-run
sequence coherent (loader → avatar → idle with zero dead ends on the happy path). The
hidden-studio story becomes a findable portfolio feature without polluting the demo frame.

## Requirements

UIX-08 (studio-mode part; first-run error honesty is 15-05's).

## Files

`src/ui/user/user-settings.ts`, `src/app/app-types.ts`, `src/app/container.ts`,
`src/style.css`, new `tests/ui-discoverability.test.ts`.

## Tasks

1. **`AppServices.uiMode` seam:** add `uiMode: { getMode(): 'user'|'studio'; set(mode:
   'user'|'studio'): void; toggle(): void }` to `AppServices` (`app-types.ts`); `container.ts`
   passes the existing `UiModeController` (already has exactly these methods — pure wiring).
   UI components may never import `ui-mode.ts` directly (composition-root-only rule,
   11-06 prohibition).
2. **Settings modal "Studio" row:** in `user-settings.ts` `buildForm()` append a
   `.form-group.settings-studio-row` containing:
   - a checkbox switch (`input[type=checkbox]` styled with `.engine-toggle` pattern) with
     `id` + `<label for>` (a11y from 15-04 helpers), label from slot
     `settings.studioMode`, initial `checked` from `services.uiMode.getMode() === 'studio'`;
   - a `drawer-subtitle` hint with the shortcut: slot `settings.studioModeHint`
     ("Ctrl+Shift+D") — text only, no kbd styling needed;
   - change handler → `services.uiMode.set(checked ? 'studio' : 'user')`.
   - **Lock respect:** if `store.isLocked('uiMode')`, render the row disabled with the
     lock tooltip (reuse `applyLock` pattern) — an embedded/locked deployment must not
     leak the toggle as usable.
3. **Mode-switch UX:** when `uiMode.set('studio')` runs while the modal is open, close the
   modal (`ui.modal.close()`) so the shell appears immediately (StudioShell.open already
   happens in container when mode changes — verify no double-open; container currently
   opens only at start — ADD a store/uiMode subscription in `container.ts`:
   `uiMode.set` already persists; subscribe to `store` changes of `user.uiMode` and call
   `shell.open()`/`shell.close()` accordingly).
4. **Esc/gear parity:** ensure the gear modal (with the new row) renders correctly in
   light theme (tokens from 15-01) and the row reads as the LAST settings group (below
   scene preset), visually separated with a `border-top: 1px solid var(--border-subtle)`.
5. **`?studio=1` + shortcut remain untouched** — this plan changes zero lines in
   `ui-mode.ts` (verified behavior: URL param > persisted; lock blocks switching). The
   README mention is Phase 13's job (noted in 15-VERIFICATION §6 handoffs).
6. **First-run coherence check (happy path, no failures):** with default settings the
   visitor sees: status "Gotowy" + brand (top-left), avatar center with loader pill
   top-center (15-03) → hides on `avatar:loaded` (container.ts:105), dock (bottom), algo
   panel (bottom-right), gear (top-right). Verify in dev at 1920×1080 + 1280×720 that no
   element overlaps another during load → fix minor overlaps found (e.g. caption box
   bottom:92px vs dock height after 40px buttons — adjust `.user-captions` bottom to
   `calc(24px + 56px + var(--space-2))` if needed).
7. **`tests/ui-discoverability.test.ts`** (jsdom, fake PanelContext):
   - Settings form contains the studio row; checkbox `checked` reflects
     `services.uiMode.getMode()`.
   - Toggle change → `services.uiMode.set` called with `'studio'`.
   - `store.isLocked('uiMode') === true` (fake store) → checkbox `disabled` + tooltip
     present.
   - `app-types.ts` compile-time: `AppServices` includes `uiMode` (type test).
8. **Copy slots:** `settings.studioMode` ("Tryb studio"), `settings.studioModeHint`
   ("Skrót: Ctrl+Shift+D"). Add to `copy.ts` + count test.

## Test/verification strategy

- New jsdom test pins the toggle semantics + lock respect.
- Manual: enable lock via Studio → Sesja → lock `uiMode` → switch to user mode → verify
  settings row disabled (embedded-deployment scenario).
- Manual walkthrough documented in 15-VERIFICATION §4.

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| `uiMode.set` inside a modal open loop (set→store change→shell open→?) | Subscription lives in container (composition root) and only calls shell.open/close — no re-entry into ui-mode |
| Studio toggle makes non-technical visitors wander into dev tools | Row is bottom-most, subtitle explains purpose; the mode is fully reversible; locks exist for embedded cases |
| Persistence surprises: URL `?studio=1` wins over saved user mode | That is pre-existing documented ui-mode behavior (URL param intentionally wins); test asserts no regression |
