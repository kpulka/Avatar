# Plan 15-04: Accessibility pass — live regions, tablist keyboard, labels, forms, SVG icons

## Goal

Close the a11y findings from 15-CONTEXT §3.2 (A1–A11) and the icon mandate (UIX-10): make
the user layer fully operable by keyboard + screen reader, wire the studio tablist to the
WAI-ARIA Tabs pattern, associate every form control, kill the Esc double-behaviour, and
replace user-layer emoji with inline SVG.

## Requirements

UIX-04, UIX-10.

## Files

See frontmatter. New test: `tests/a11y-dom.test.ts` (jsdom).

## Tasks

1. **Live regions (finding A1):**
   - `captions.ts`: root `.cinema-captions` gets `role="log"` + `aria-live="polite"` +
     `aria-label` slot `captions.regionAria`.
   - `status-pill.ts`: the state `<span>` gets `role="status"` (label flips announce).
   - `algorithm-switcher.ts`: `statusLine` gets `role="status"` + `aria-live="polite"`.
   - Decorative `pulse-dot` → `aria-hidden="true"` (finding A11).
2. **Studio tablist → WAI-ARIA Tabs (finding A6):** in `studio-shell.ts`:
   - Roving tabindex on `.studio-tab` buttons: active tab `tabindex=0`, others `-1`.
   - ArrowLeft/ArrowRight/Home/End move focus + select (select-on-focus, immediate
     `openTab`); Home/End jump to first/last.
   - Each tab gets `id` (`tab-{panelId}`) and `aria-controls="panel-{panelId}"`; the drawer
     body gets `role="tabpanel"`, `id="panel-{panelId}"`, `aria-labelledby` → active tab id,
     re-pointed on every `openTab`.
   - Tab clicks already select — keep; ensure focus ring visible with tokens.
3. **Form label association (finding A7):** every `<select>`/`<input type=range>` gets an
   `id` (uid from 15-03) and its `<label>` gets `for`:
   - `user-settings.ts`: volume/mic/theme/preset (4 groups) — wrap label text + keep `for`.
   - `a2f-panel.ts`: URL input gains a visible `<label for>` (slot `a2f.urlTitle` reused).
   - `session-panel.ts`: agent input + volume slider.
   - `animation-panel.ts`: 9 calibration sliders (label `for` + value `<span id>` with
     `aria-live="off"`— value is readable from the label text itself).
4. **Keyboard-reachable file upload (finding A8):** `scene-panel.ts` — replace the
   `<label class="btn">` + `display:none` input with a real `<button type="button">` that
   calls `importInput.click()`; keep the hidden input but drop `display:none` in favor of
   the `.hidden` class + `tabindex="-1"` + `aria-hidden="true"` (still functional for
   click()). Same treatment for the profile import input in `session-panel.ts:106-107`.
5. **Esc hygiene (finding A10):** in `container.ts` `onKeydown` — before toggling
   presentation, bail out when `document.querySelector('dialog[open]')` exists (native Esc
   closes the dialog; presentation must not flip). Keep `h`/`H` behavior.
6. **SVG icons (UIX-10):** add `src/ui/shared/icons.ts` with exported inline-SVG builders
   (`mic`, `micOff`, `stop`, `interrupt`, `settings`, `presentation`, `close`, `dot`) —
   16×16 Lucide-style paths, `currentColor`, `aria-hidden`. Replace emoji in:
   `conversation-dock.ts` (🎙️/🎤/🛑), `user-settings.ts` gear (⚙️), `container.ts`
   presentation button (👁️ — text label carries meaning, icon decorative),
   `studio-shell.ts` close buttons (✕), `panel-registry.ts` — none (text). Studio panel
   icons in tab buttons may stay emoji (spec-tolerated) EXCEPT `studio-shell.ts` close.
   Buttons keep their visible text labels (11-UI-SPEC rule: icon is never sole meaning).
7. **`prefers-reduced-motion` completion (finding A9):** add `.btn-call.active`,
   `.spinner`, `.toast`, `.loader-overlay` to the reduced-motion block (animations/transitions
   off), and add `.toast-stack` transitions.
8. **`.engine-toggle` styling (finding V8):** style as a proper row: flex, `gap: --space-2`,
   `min-height: 36px`, `align-items: center`, checkbox `accent-color: var(--accent)`;
   `.icon-label` styled like `.btn-label`.
9. **`tests/a11y-dom.test.ts`** (jsdom, mock-free where possible):
   - tablist: `aria-selected`/`tabindex` sync on select; ArrowRight moves focus + selects;
     Home/End; `aria-controls` ↔ `role=tabpanel` ids match.
   - captions: `role="log"` + `aria-live` present after mount (mount via fake PanelContext
     from panel-registry tests).
   - user-settings form: every select/input has a label with matching `for`.
   - file upload: button is a `<button>`, no `<label class="btn">` pattern; clicking it
     triggers the hidden input click (spy).
   - icons: dock buttons contain `svg[aria-hidden="true"]` + visible `.btn-label` text.
10. Manual keyboard-only pass script (into 15-VERIFICATION §2): Tab order
    status→dock(start,mute,interrupt)→segment→compare→blind→gear; open settings with
    Enter; close with Esc; Ctrl+Shift+D; tablist arrows; upload button focusable.

## Test/verification strategy

- New `tests/a11y-dom.test.ts` pins the structural guarantees (roles, ids, keyboard).
- Manual pass per 15-VERIFICATION §2 (keyboard-only, screen-reader smoke optional at
  owner's discretion).
- Contrast: spot-check computed pairs in both themes against 4.5:1 (part of 15-01
  acceptance screenshots — re-verify after this plan since icons change foreground usage).

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| Roving tabindex regresses mouse users (click focus quirks) | Select-on-click preserved; click sets tabindex=0 on the clicked tab (standard pattern), test covers click path |
| Label `for` + uid collides with existing ids | `uid()` counter prefix `a15-`; grep confirms no `a15-` ids pre-exist |
| SVG builders bloat each mount (52 inspector sliders etc.) | Icons only on user layer + shell chrome; panels keep emoji per spec tolerance |
| Esc guard makes Escape do nothing when a native dialog failed to open once | Guard reads the live DOM (`dialog[open]`) each keypress — no stale state |
