# Plan 15-07: Responsive integrity, layout polish & end-of-phase hardening

## Goal

Add the missing viewport layer (15-CONTEXT §3.4: zero breakpoints exist today) so the app
holds at 1920×1080 / 1440×900 / 1280×720 / 1152×648, close the remaining layout nits
(captions/dock spacing, drawer widths, telemetry grid), and run the final regression sweep
that guards every prior plan's gains. This is the last execute plan — it ends with the
verification protocol (15-VERIFICATION.md) ready for the human UAT.

## Requirements

UIX-07, UIX-11.

## Files

`src/style.css`, `src/ui/studio/studio-shell.ts` (aria attributes only if needed), new
`tests/responsive-layout.test.ts` (static CSS analysis + shell DOM test).

## Tasks

1. **Guard queries in `style.css`** (desktop-first, minimum 1152×648 per 15-CONTEXT §5.3):
   - `@media (max-width: 1440px)`: `.user-algo` max-width 240px → 220px; studio right
     drawer 380px → 340px; captions max-width 720px → 640px.
   - `@media (max-width: 1280px)`: `.user-algo` collapses to icon-column — hide
     `.algo-status` line clamp to 1 line; captions bottom rises above the algo panel's
     top edge (compute: dock ~56px + captions offset) — set `.user-captions { max-width:
     520px; left: 50%; }` shifted clear of `.user-algo` (which is right-anchored); studio
     left drawers 340px → 300px; `.studio-left-toggles` gap shrinks.
   - `@media (max-width: 1152px)`: emergency collapse — dock buttons icon-only
     (`.dock-btn .btn-label { display: none }`, keep aria-labels!), `.user-algo` hidden
     behind a `.user-algo-collapsed` icon button? **NO — do not add JS**; instead shrink:
     algo panel becomes a compact row (segment + compare only, blind toggle +
     status hidden but still in a11y tree via `.sr-only` class — add `.sr-only` utility);
     captions max-width 480px. Everything must remain OPERABLE, not merely visible.
   - Add `min-width`/`min-height` documentation comment: "Supported minimum: 1152×648".
2. **`.sr-only` utility** (visually hidden, screen-reader exposed) — needed by task 1 and
   available for future use.
3. **Caption/dock geometry final pass:** with 40px dock buttons (15-01) the dock is ~56px
   tall + 24px offset; set `.user-captions { bottom: calc(80px + var(--space-2)); }` and
   verify the 3-line clamp (15-05) never underlaps the dock at 720p. Vignette overlay stays
   `z-index: var(--z-vignette)` below chrome.
4. **Telemetry grid polish:** `.telemetry-grid` gets `grid-template-columns: minmax(0,1fr)
   minmax(0,1fr)` (already 1fr 1fr — make resilient to long values with `minmax(0,1fr)`) +
   `word-break` for the ALIGN row.
5. **Drawer scroll audit:** confirm `.drawer-body` is the ONLY scroll container in drawers
   (it is — style.css:431-438) and that `.viseme-shape-sliders` nested scroll
   (style.css:920) doesn't double-scroll at 720p drawer height (`top:72px; bottom:24px` →
   ~552px at 648 height): change `.viseme-shape-sliders { max-height: 44vh }` →
   `max-height: min(44vh, 300px)`.
6. **`tests/responsive-layout.test.ts`:** static analysis of `src/style.css`: (a) contains
   the three guard queries (`max-width: 1440px/1280px/1152px`); (b) `.sr-only` defined;
   (c) `.user-captions` uses `bottom: calc(`; (d) no `!important` introduced in media
   queries except the pre-existing `body[data-mode="user"] .studio-shell` and
   `presentation-mode` rules (whitelist); jsdom part: dock buttons in the 1152px collapse
   class still expose `aria-label` (mount dock, assert every `dock-btn` has aria-label —
   guards the icon-only collapse).
7. **Final sweep (UIX-11 audit):**

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| Icon-only dock at 1152px hides what buttons do for sighted users | aria-labels + `title` tooltips survive; 1152×648 is an edge tier below the declared 1280×720 comfort target |
| Nested scroll fix (task 5) hurts tall viewports | `min(44vh, 300px)` keeps the original behavior above ~720px height |
| Responsive rules drift from later manual tweaks | Static test + the TOC section keeps the responsive block identifiable and single |
