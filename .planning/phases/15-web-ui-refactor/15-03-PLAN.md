# Plan 15-03: Shared primitives contract (toast / modal / loader / dom helpers)

## Goal

Bring the three shared primitives up to a documented, testable contract (spec:
`15-DRAFT-ui-spec.md` §3): dismissible accessible toasts, a modal with visible close and
proper labelling, a loader that always clears and never hides under the dock, plus the small
`dom.ts` extensions the other plans need (`aria-hidden` builder, `id` helper). These
primitives are the foundation for 15-04 (a11y), 15-05 (states) and 15-06 (discoverability).

## Requirements

UIX-03, UIX-11.

## Files

`src/ui/shared/{toast,modal,loader,dom}.ts`, `src/style.css`, new `tests/shared-ui.test.ts`
(jsdom).

## Tasks

1. **`dom.ts`** — extend `ElOptions` with `role?: string`, `hidden?: boolean`; add
   `export function uid(prefix: string): string` (prefix + counter) for `aria-controls`
   wiring; keep everything `textContent`-only.
2. **`toast.ts` — rebuild to contract C-1 (UI-SPEC §3.1):**
   - Root: `role="status"` default, `role="alert"` when `type === 'error'`;
     `aria-live` implicit via roles; `aria-atomic="true"`.
   - Errors stay until dismissed; success auto-hides 5 s (unchanged semantics).
   - Add a close `<button>` (icon-only, `aria-label` from slot `shared.dismiss`) shown ONLY
     on persistent error toasts.
   - Support **up to 3 stacked toasts** (append children instead of replacing one node's
     text — fixes the single-slot overwrite, 15-CONTEXT A4/S6); older toasts stay until
     dismissed/timeout. `ToastHandle` gains `show(message, type)` (same signature) — existing
     call sites unchanged.
   - `destroy()` removes all nodes + clears timers.
3. **`modal.ts` — rebuild to contract C-2:**
   - `dialog` gets `aria-labelledby` → the header `h3` (uid).
   - Header row gains a visible close `<button>` (`aria-label` slot `shared.close`) — works
     in both `showModal` and the `open`-attribute fallback.
   - Fallback path (no `showModal`): add a focus trap — keydown Tab handler cycling
     focusables — and Esc-to-close on the dialog element; restore focus to the invoker on
     close (store `document.activeElement` at `open()`, refocus at `close()`).
   - `open(title, content)` signature unchanged.
4. **`loader.ts` — rebuild to contract C-3:**
   - Root gains `role="status"` + `aria-live="polite"`.
   - Add `error(message: string): void` — swaps spinner for a destructive icon + retry hook
     (`onRetry?: () => void` passed via `createLoader(container, { onRetry })`), so 15-05
     can surface the avatar double-failure inside the loader itself (finding S1).
   - `hide()` clears BOTH states (busy + error).
   - CSS: `.loader-overlay` moves to `--z-loader` (60) — above dock (40) — and repositions
     to top-center (`top: 16px; left: 50%; transform: translateX(-50%)`) so it never sits
     behind the dock visually (findings S2). Style `.loader-error` variant with
     `--destructive` tokens.
5. **`style.css`**: `.toast-stack` (fixed bottom-right, `z-index: var(--z-toast)`, flex
   column, gap `--space-2`, `max-width: 360px`); `.toast` gets `display:flex`,
   `justify-content: space-between`, close-button styles (`.toast-close`); `.loader-overlay`
   top-center + `--z-loader`; `.loader-error` variant. All tokens from 15-01.
6. **`tests/shared-ui.test.ts`** (`// @vitest-environment jsdom`):
   - toast: 3 consecutive `show()` → 3 nodes; error toast has `role="alert"` + close button;
     success toast has `role="status"` + no close button; close click removes node;
     `destroy()` clears all.
   - modal: `open()` sets `aria-labelledby` matching the h3's `id`; close button calls
     `close()`; fallback path (`dialogEl.showModal` undefined in jsdom) traps Tab (first
     focusable focused on open).
   - loader: `role="status"` present; `error()` shows error class + retry button invokes
     callback; `hide()` after error clears.
7. Verify `container.ts` wiring still works untouched (`events.on('toast') → toast.show`,
   `avatar:loaded → loader.hide`) — no container changes in this plan.

## Acceptance criteria

- [ ] `npm test` green (existing + `tests/shared-ui.test.ts`)
- [ ] `npm run build` green
- [ ] Error toast: visible X, `role="alert"`; success toast: `role="status"`, auto-hide
- [ ] Three toasts never overwrite each other (manual dev check: trigger mute + interrupt)
- [ ] Settings modal shows a visible close button; Esc and X both close it; focus returns
      to the gear
- [ ] Loader pill renders top-center above the dock while loading; `role="status"` present
- [ ] All new UI uses only `t()` slots (diacritics gate from 15-02 stays green)

## Test/verification strategy

- New `tests/shared-ui.test.ts` (jsdom) pins the contract mechanically.
- Manual: trigger each primitive in dev (toast via mute, modal via gear, loader via reload)
  in BOTH themes.
- 15-04 and 15-05 build directly on these handles — contract drift breaks their tests, not
  vibes.

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| Stacked toasts change geometry callers assumed (bottom-right single) | Only `.toast-stack` container changes; no TS consumer reads toast DOM |
| `<dialog>` focus trap in fallback path conflicts with native behavior | Trap only installs when `showModal` is unavailable (guard by feature detection); native path needs nothing |
| Loader top-center may cover the status pill (top-left) on short viewports | Loader is centered, status is left-anchored 16px; 1152×648 manual check in 15-07 acceptance |
