<tasks>
1. **Scheduler scratch structures (A-1, A-2, A-3).** In `viseme-scheduler.ts`: hoist `targets` Map (:79) and `updated` Map (:120) to preallocated instance fields (`this.scratchTargets`, `this.scratchUpdated`), `.clear()` at frame start (Map.clear keeps capacity). Replace `this.queue = this.queue.filter(...)` (:82) with in-place compaction: write-index loop over the array, `queue.length = writeIdx` after — O(n) time, zero allocation. Constructor takes an optional `expectedShapes` hint to presize the scratch Maps (FaceController passes its shape count).
2. **Emotion layer (A-4, A-5).** `emotion-layer.ts`: `allShapes` Set (:113) and the defensive copy `new Map(this.activeWeights)` (:134) become reused instance scratch (`clear()` per frame). The defensive copy existed because callers mutate the returned map — audit callers in face-controller.ts (the only consumer) and switch to a documented borrow contract: `peekWeights(): Readonly<Map>` (borrowed) + `takeWeights()` (copy, used by non-hot paths like RELAXING entry snapshot). D-12's `analyzeText` keyword arrays: hoist the arrays to module consts (they are literals per call today).
3. **Frames path (A-6, A-7).** `face-controller.ts`: the `endTurn` closure (:475) becomes a private method `endTurnIfDrained()` (no closure allocation per frame). `buf.slice(idx)` (:508) → in-place compaction of `frameBuffer` (same write-index pattern as task 1). Binary search stays.
4. **Gaze + blink (A-8, A-9).** `gaze-saccades.ts`: the `EyeGazeWeights` literal (:81-93) and `Object.entries` in applyToDriver (:101) → reusable instance objects + a fixed 8-key loop over a hoisted key array (eyeLook L/R × 4 dirs). `procedural-blink.ts`: the `{left, right}` return object (:88-91) → one preallocated instance object mutated in place (single consumer — FaceController render; document the borrow).
5. **RELAXING writes (A-10).** In the RELAXING branch (face-controller.ts:610-622): skip the driver write for shapes where `|current - target| < snapEpsilon` AND current < snapEpsilon (both ~0) — the zero-to-zero writes over 52 shapes × sub-meshes vanish; completion check uses maxWeight as today.
6. **meta.shapes Set (context §7 tail).** `face-controller.ts:525` `meta.shapes.indexOf(shape)` → a `Set` built once per clip (frames meta) or per override application, stored next to the meta; per-frame lookups are O(1) with no scan.
7. **Allocation counters.** Add a lightweight opt-in probe: `src/lipsync/alloc-probe.ts` exporting `allocProbe = { enabled: false, count: 0, reset() }` — instrumented sites call `allocProbe.record()` ONLY in the replaced code paths that would have allocated (guard `if (allocProbe.enabled)`), i.e. every place a scratch reuse replaced a fresh allocation. Zero cost when disabled (branch predictor). FaceController option `debugAllocations: boolean` flips it for tests.
8. **`tests/hot-path-allocations.test.ts`:** (a) enable probe → feed a synthetic viseme turn → step render 120 frames → `allocProbe.count === 0`; (b) same for a frames turn (feedFrames + 120 renders); (c) golden-weight regression: capture weights at frame 60 pre-change (record literals in the test) → identical within 1e-9; (d) RELAXING after A-10: driver mock counts `applyWeight` calls → near-zero calls for all-zero shapes, still correct completion.
