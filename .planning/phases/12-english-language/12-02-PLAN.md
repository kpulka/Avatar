# Plan 12-02: Docs translation — wave 1 (core: roadmap, architecture, EL integration)

## Goal

Translate the three foundation docs (92 + 137 + 186 lines) to English with structure and
section numbering preserved, terminology per the glossary.

## Requirements

I18N-02 (partial: 3 of 10 files).

## Files

- `docs/0-roadmap-poc-mvp.md` (92 lines, 173 diacritics)
- `docs/1-architecture-and-3d-models.md` (137, 120)
- `docs/2-elevenlabs-wss-integration.md` (186, 141)

## Tasks

1. **Pre-flight**: read the whole file; list its outbound relative links; confirm each
   target is the post-rename canonical name (from 12-01) — fix targets as part of this
   translation (these three docs' links were counted in 12-CONTEXT §2).
2. **Translate** prose, headings, table headers/cells, code-block comments, figure
   captions. Preserve EXACTLY: section order and `## N` numbering (§2 of CONTEXT —
   cross-doc `§N` refs depend on it), tables' columns/rows, ASCII diagrams (labels may be
   translated inside them), lists' nesting. Do not restructure, do not "improve" content,
   do not drop stale-sounding passages (truthfulness is Phase 13's README concern; docs
   are historical canon).
3. **Terminology discipline**: every glossary term (12-DRAFT-glossary.md) rendered with
   its canonical EN equivalent; keep the PL original in parentheses on FIRST occurrence of
   genuinely PL-specific concepts only (digraphs, nasal vowels, control sentences like
   `szczypczyzna` — the phonetic DATA stays PL, glossed in EN).
4. **Technical tokens stay verbatim**: API/event/field names (`agent_response_correction`,
   `char_start_times_ms`, `morphTargetInfluences`), file paths, URLs, config keys.
5. Commit: `docs(i18n): translate core set (0-roadmap, 1-architecture, 2-elevenlabs) to English`.
