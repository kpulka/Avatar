# Phase 11.2 Plan 07: Audible-clock lip-sync Summary

FaceController now samples visemes at the time actually heard (`getOutputTimestamp`, else `currentTime - outputLatency - baseLatency`, monotonic), and the hand-tuned 90/100/120 ms sync offsets are reduced to 20/30/40 ms residuals with a one-time migration of saved calibrations.

## Delivered

- `src/audio/audible-clock.ts`: `getAudibleTime(ctx, nowMs)` and `createAudibleClock(ctx)` (monotonic guard). 5 unit tests.
- `FaceController` takes `options.audibleClock` (default `createAudibleClock(engine.ctx)`); `render()` uses it for `nowSec` (viseme scheduler and frames track).
- `calibration.ts`: presets 20/30/40, `LEGACY_SYNC_OFFSETS`, `SYNC_CLOCK_VERSION = 2`, `clockVersion` on the profile (presets carry it).
- `settings-schema.ts` `sanitizeCalibration` migrates once: stored legacy preset values map 90/100/120 -> 20/30/40, any other stored value -> `clamp(v - 70, -150, 400)`, then `clockVersion = 2`. Already-v2 values untouched; idempotent; if no offset was stored the default is kept.

## Gate

- `npx tsc --noEmit` clean, `npm run build` OK, `npx vitest run`: 49 files, 256 tests passed (baseline 245, +11 new).

## Deviations from Plan

1. **[Rule 3 - Blocking] `tests/calibration.test.ts` edited (outside the plan's files_modified).** It hard-coded the old default `syncOffsetMs === 100` (2 assertions) and a `toEqual` of a custom profile that now also carries `clockVersion`. Updated to 30 and added `clockVersion: 2` to the custom fixture. Unavoidable consequence of the preset change the plan mandates; no thresholds lowered, no test skipped.
2. **`clockVersion` is a required field (`number`), not optional as the plan wrote.** Optional made `animation-panel.ts` (`SLIDERS` keyed by `keyof CalibrationProfile`, outside this plan's lock) fail `tsc` with `number | undefined`. Presets carry `clockVersion: 2`, so every code path that spreads a preset/profile keeps it (`animation-controller` setCalibration/applyPreset/reset all spread whole objects), which also prevents repeated migration.
3. **Face-controller test uses audible time 0.9 s, not 0.99 s**, as the plan suggested: the scheduler blend-in window is 35 ms, so at 10 ms before onset the weight is already ~0.48. 0.9 s is clearly before blend-in.
4. `loadCalibrationProfile` / `saveCalibrationProfile` in `calibration.ts` (legacy direct localStorage helpers, unused by `src/`) are NOT migrated; the live path is `settings-schema` / `migrate.ts`.
