# Plan 14-02: Layering contract + import-graph gate

## Goal

Freeze the measured layer stack (14-CONTEXT §1.1) as a machine-checked contract: a
`tests/layering.test.ts` gate that parses static imports of every `src` module and fails
`npm test` on any edge the contract doesn't allow — with the rules exported as data so
Phase 18's ESLint can enforce the same table in the editor.

## Requirements

ARCH-01 (layering contract + gate), ARCH-06 (side-effect rule).

## Files

- `tests/layering-rules.ts` — NEW: the allow-table as exported data
- `tests/layering.test.ts` — NEW: the gate (fs walk + import resolution + assertions)

## Tasks

1. Encode the contract in `tests/layering-rules.ts` as data (this exact structure is what
   18-04's ESLint config imports):

   ```ts
   export const LAYER_ORDER = ['types','core','scene','prod','realism','avatar','audio','lipsync','features','ui','app-root'] as const;
   export const MODULE_RULES = {
     // contract modules inside app/ — importable by features/ui
     'app/app-types.ts': { layer: 'app-contracts', importableBy: ['features','ui','app-root'] },
     'app/events.ts':    { layer: 'app-contracts', importableBy: ['features','ui','app-root'] },
     'app/ui-mode.ts':   { layer: 'app-contracts', importableBy: ['features','ui','app-root'] },
     'app/container.ts': { layer: 'app-root', importableBy: ['main.ts'] }, // nobody else
     // per-directory defaults from 14-CONTEXT §1.1 …
   };
   export const EXCEPTIONS = [
     { from: 'audio/a2f-backend.ts', to: 'lipsync/a2f-parser', reason: 'A2F JSON parse (dir-level audio↔lipsync pair; see 14-CONTEXT §1.1)' },
     { from: 'lipsync/face-controller.ts', to: 'audio/audio-engine', reason: 'speech pipeline drives AudioEngine (paired exception above)' },
     { from: 'app/store/*', to: 'audio|lipsync', reason: 'schema needs domain defaults/types (documented)' },
   ];
   ```

   The measured baseline (§1.1) must pass **unchanged** — the gate freezes today's shape,
   it does not invent an aspirational one.
2. `tests/layering.test.ts`:
   - Walk `src/**/*.{ts,css}` (fs, like `tests/language.test.ts`), parse static imports
     (`/^import .*? from '(\.[^']+)'/gm` + bare `import '…'`), resolve `../` chains to
     repo-relative paths (ignore `.css` targets except recording them).
   - Assert per-module: every resolved edge is allowed by `MODULE_RULES`/`LAYER_ORDER`
     (lower layer may not import higher; `ui → features` stays forbidden at 0 edges;
     `container.ts` importers == `['main.ts']`).
   - **Side-effect rule** (ARCH-06): assert no module under `src/{core,scene,realism,avatar,audio,lipsync,features,prod,types}`
     touches `document`/`window`/`localStorage` at module top level (regex over statements
     outside function/class bodies — same tolerance approach as the language gate's
     line-patterns; false positives get an explicit exemption entry with a reason).
3. Run the gate against the tree BEFORE adding any new rule: it must pass with the measured
   exceptions and zero surprise violations (a violation here means §1.1 was wrong — fix the
   CONTEXT, not the code).
4. Negative test: include a self-test that a synthetic forbidden edge
   (`features/x.ts → ui/y.ts`) is rejected (guards the gate against a regex that silently
   matches nothing).
5. Commit: `test(arch): layering gate — measured import contract as data`.

## Acceptance criteria

- [ ] `npm test` runs the layering gate and it passes on the current tree (baseline frozen)
- [ ] Gate catches a synthetic `features → ui` import (negative self-test)
- [ ] `tests/layering-rules.ts` exports rules as data (no test logic inline) — importable
      by an ESLint config without a vitest runtime
- [ ] Exceptions list contains exactly the 3 documented groups, each with a reason string
- [ ] Side-effect rule green on current tree (or exemptions with reasons)

## Test/verification strategy

The gate is the test. 14-VERIFICATION re-runs it; 18-04 imports the same rule data for
ESlint `no-restricted-imports`/boundary config and CI keeps both honest.

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| Regex import parsing misses dynamic `import()` (e.g. lazy CMU dict in `g2p-en.ts`) | Gate parses dynamic imports too (one extra regex); the g2p lazy import is `node_modules`, not a local layer edge — assert that explicitly |
| False-positive side-effect matches (three.js top-level canvas refs in `core/`) | Exemption entries with reasons; prefer narrowing the regex over exempting whole files |
| Contract data drifts from ESLint config in 18 | Single source: 18-04 imports THIS file; the retro (14-06) checks the import actually happens |
