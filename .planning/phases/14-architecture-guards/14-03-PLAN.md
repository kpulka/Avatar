# Plan 14-03: Lifecycle guarantee — dispose regression test

## Goal

Turn the P11 "zero leaks" discipline into a machine guarantee: after `container.dispose()`
the event bus holds zero handlers and the teardown contract is asserted by a test — so a
future `events.on(...)` added without a matching `Unsub` fails CI instead of leaking in
production.

## Requirements

ARCH-03 (lifecycle guarantee, handlerCount assertion). ARCH-04's bus-invariant half
(documented + already tested in `tests/events.test.ts` — extended here only).

## Files

- `src/app/events.ts` — add `handlerCount(): number` (test/debug only)
- `tests/container.test.ts` — dispose regression
- `tests/events.test.ts` — `handlerCount` unit coverage

## Tasks

1. Add to `TypedEventBus` (next to `clear()`, ~events.ts:47):
   `public handlerCount(): number { let n = 0; for (const s of this.handlers.values()) n += s.size; return n; }`
   with a comment marking it test/debug-only (not for feature logic). Add
   `disposables().size()` already exists (:68-70) — no change needed there.
2. Unit tests in `tests/events.test.ts`: `handlerCount` reflects `on`/`off`/Unsub calls
   and returns 0 after `clear()`; idempotent Unsub doesn't double-decrement (guards the
   `active` flag at events.ts:23-28).
3. Dispose regression in `tests/container.test.ts` (the file already constructs the
   container in jsdom — extend it):
   - construct container → `start()` (or as far as the existing test goes — mirror its
     setup, including any loader/avatar mocks it uses);
   - record `bus.handlerCount()` as `afterStart` (> 0 — subscriptions exist);
   - call `container.dispose()`;
   - assert `bus.handlerCount() === 0` AND `disposables().size() === 0` where a collector
     instance is reachable; assert a second `dispose()` doesn't throw (idempotence —
     cheap insurance, matches the Unsub idempotence philosophy).
   - If the bus instance isn't currently exposed for tests, expose it minimally through
     the container's test surface (e.g. a readonly field or a debug getter) — additive
     only, no signature changes.
4. The teardown CONTRACT (what dispose must release: rAF, 3 window listeners, 9 Unsubs,
   shell, 5 controllers, toast/loader/modal/environment/loader — container.ts:314-339)
   gets a table in the 14-05 ARCHITECTURE.md draft; this plan only asserts the bus-level
   invariant, not each individual step (those are implementation details that may grow).
5. Commit: `test(app): dispose leaves zero bus handlers (lifecycle regression)`.

## Acceptance criteria

- [ ] `handlerCount()` exists, unit-tested, marked test/debug-only
- [ ] `tests/container.test.ts` asserts bus handler count → 0 after dispose (and
      `afterStart > 0` first, so the test can't pass vacuously on an empty bus)
- [ ] Second `dispose()` doesn't throw
- [ ] `npm test` green (204+ tests + the new ones)

## Test/verification strategy

jsdom-based lifecycle test is the verification; 14-VERIFICATION §2 runs it and greps the
bus for post-dispose handlers as a belt-and-braces check during UAT.

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| jsdom container construction depends on WebGL mocks that may drift with 16-02's container rewiring | The existing container.test.ts is the harness — extend, don't rebuild; if 16 lands first, validate against its gaze-provider teardown |
| Exposing the bus for tests widens the public surface | Minimal readonly exposure documented as test surface; the layering gate (14-02) still forbids `container.ts` imports outside `main.ts` |
| Test passes with `afterStart === 0` if construction silently fails | Explicit `expect(afterStart).toBeGreaterThan(0)` precondition (task 3) |
