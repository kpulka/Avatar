# 17-03: Alignment normalization extraction + golden-span corpus

## Goal

Make the input side of the pipeline as trustworthy as the G2P side: extract the inline
alignment normalization from `speech-backend.ts` into a pure, fully-tested function; commit a
golden-span corpus fixture that pins the *end-to-end data result* (text → phonemes → spans)
for control and conversational sentences; and close the remaining rescale/fallback edge
contracts. This is the automated half of the quality harness (LIP-07).

## Requirements

- LIP-06 (malformed alignment handling as a tested pure function) — the extraction part;
  the user-mode badge part lands in 17-06.
- LIP-07 (automated part): golden-span fixtures + computed proxy metrics.

## Tasks

1. **Create `src/audio/alignment-normalize.ts`** exporting
   `normalizeAlignmentPayload(rawAlign: unknown): CharAlignment | null` — a pure
   transcription of speech-backend.ts:66-99 with identical semantics:
   - aliases: `chars|characters`, `char_start_times_ms`, `char_durations_ms`,
     `character_start_times_seconds (+ character_end_times_seconds → durations, min 25 ms)`;
   - seconds→ms conversion (×1000) as today;
   - length guards → `null` (caller falls back), matching today's `alignment = null` path;
   - `source: 'elevenlabs'` always on success (never 'energy-fallback' here).
   Export also a `CharAlignmentLike` input type = the union of accepted shapes (typed via
   a permissive `Record<string, unknown>` — no `any`).
   **`tests/speech-backend-alignment.test.ts`** (new): full unit matrix —
   happy path each alias; ms-vs-seconds equivalence; missing durations → flat 50 ms;
   mismatched lengths → null; garbage input (`null`, `42`, `{}`) → null; negative start
   times → clamp to 0 (NEW explicit behavior: today they flow through — decide and pin;
   recommendation: clamp ≥ 0 since negative can't precede the audio start); NaN times →
   drop the field set → null.
2. **Rewire `speech-backend.ts`** (:65-99) to `alignment = normalizeAlignmentPayload(rawAlign)`.
   The rescale block (:105-108) and fallback (:112-114) stay. `diagnoseSync` unchanged.
   Behavior on the happy path must be byte-identical (pin with a snapshot of the
   `[AlignDiag] first-chunk` log structure? No — keep it simple: the pure-function tests +
   existing raw-wss-client tests are the guard).
3. **Guard `alignment-rescale.ts` edges**: NaN/negative factor (already `Math.max(0, ...)`
   on durations — extend to starts: `Math.max(0, s * factor)`), and return the input
   unchanged when `factor` is non-finite (JSON-derived times can be Infinity from a buggy
   backend). Extend tests/alignment-rescale.test.ts: NaN durations, negative starts,
   single-char chunk.
4. **Fix `energy-fallback.ts` last-window**: `numSlices = Math.round` instead of `floor`
   when the remainder ≥ half a window (a 60 ms remainder on 70 ms windows counts as one
   more slice — the speech at the chunk tail gets its viseme); pin with a test
   (Pcm of exactly 1.5 windows → 2 slices). Also guard `sampleRate ≤ 0` → throw a clear
   error (currently `Math.max(1, ...)` silently produces garbage). Extend
   tests/energy-fallback.test.ts: all-zero PCM → all energies 0; odd byte length
   (Uint8Array with byteLength % 4 !== 0 → Int16Array view truncation — pin no throw).
5. **Build the golden-span corpus** `tests/fixtures/lipsync-corpus.json`:
   ```
   { "version": 1, "note": "text -> chars with synthetic-but-realistic timings -> expected spans",
     "cases": [
       { "id": "control-closure",
         "text": "Map, mop, pop.",
         "charsPerMs": 55,
         "expect": { "spans": [["M","AA","P","M","AA","P","P","AA","P"], "..."], ... } } ... ] }
   ```

   Structure per case: `id`, `text`, `charsPerMs` (uniform synthetic timing — deterministic,
   documented as NOT real audio), `expect.phonemeSequence` (the ARPAbet sequence),
   `expect.spanSumToleranceMs` (1), `expect.minSpanMs` (17.5 after the 17-02 fix),

   Include: the 7 control sentences from docs/EN-visemes.md §6, 6 conversational sentences,
   "know what" + "question" from the LIPS-05 cases, and 1 PL sentence ("szczypczyzna",
   ignored for phoneme path but proves the char-path fallback is not exercised here —
   actually: mark `"path": "char"` for it and have the test skip span expectations; keep
   it as a char-path tokenizer regression instead).
6. **`tests/lipsync-corpus.test.ts`** (new): for every case, synthesize the CharAlignment
   from `text` + `charsPerMs` (each char start = idx×ms, duration = ms), run

## Test/verification strategy

- Backstops: all existing audio/lipsync tests (alignment-rescale, energy-fallback,
  phoneme-merge, raw-wss-client, barge-in-pipeline, race-condition-epoch).
- The new corpus test is the permanent end-to-end pin: any regression in lexicon content
  (17-01), OOV rules, merge weighting, or rescale shows up here as a sequence/span failure.
- The distinctness proxy is computed once and frozen — a table edit that collapses two
  viseme groups fails the build until consciously re-baselined.

## Risks & mitigations

- **Exact-sequence equality is brittle to intentional future table/lexicon changes** →
  that is the point (deliberate review gate); updating the fixture is a conscious,
  reviewable diff with a one-line "why" comment per changed case.
- **Synthetic uniform timings ≠ real EL alignment** → explicitly documented in the
  fixture header; real-alignment UAT is 17-05. The fixture pins *data-pipeline* logic
  (parsing, G2P, weighting), not timing realism.
- **Negative-time clamp changes behavior on a malformed stream** → strictly more robust;
  a backend that sends negatives today gets garbage jaw positions; clamp to 0 is the only
  sane reading. Pinned by test.
- **Extraction drift from speech-backend** → the pure fn is a transcription, not a
  rewrite; the speech-backend diff is ~10 lines (call site only); code review verifies.
