# 17-02: Merge timing hardening + table/doc reconciliation

## Goal

Fix the one real timing bug in the signal pipeline (MIN_SPAN_MS overflow — short words bleed
into the next word's time window), implement the doc-recommended diphthong motion in the merge
layer, close the table-vs-doc drift, and dissolve the `testPhoneme` pose duplication. After
this plan the merge and the table are *provably* aligned with docs/EN-visemes.md, and every
number has one home.

## Tasks

1. **Fix MIN_SPAN_MS overflow in `phoneme-merge.ts`** (currently :24 `MIN_SPAN_MS = 35` and
   :76-84 `durationMs = Math.max(MIN_SPAN_MS, ideal)` with an unchecked advancing cursor):
   - First add a **pinning test** of current behavior (word "eye" with 100 ms window →
     spans sum > 100 ms — documents the bug), then fix:
   - New algorithm per word: compute ideal durations (weights 1.2/0.8) exactly as today;
     if `Σ max(MIN_SPAN_MS, ideal) > wordSpanMs`, apply a **second normalization pass**:
     scale the clamped durations down so their sum equals `wordSpanMs`, floor at
     `MIN_SPAN_MS / 2` (17.5 ms) — if even that floor cannot fit (pathological ~3-phoneme
     20 ms words), divide `wordSpanMs` equally. Invariant, test-asserted per word:
     `Σ span.durationMs === wordSpanMs` and `last.start + last.duration === wordEnd`
     (± 1 ms rounding). The cursor NEVER advances past the word end.
   - Keep the existing invariant test (phoneme-merge.test.ts:37-50) green — it must now
     hold for *all* words, not just the fixture.
2. **Degenerate-edge tests for the merge** (extend tests/phoneme-merge.test.ts):
   - zero-duration word (all char durations 0 → `wordSpanMs ≤ 0`) → word skipped, no spans,
     neighbors unaffected (pins current phoneme-merge.ts:65-68 behavior);
   - missing start times (`starts[firstIdx] === undefined` → `?? 0` anchor at chunk start) —
     pin that the word lands at 0, do not silently shift (current :63);
   - single-phoneme word ("I") spans exactly the word window;
   - a two-word chunk where word 1 is pathological-short and word 2 normal — assert word 2
     spans are unaffected by word 1 (the exact regression the fix targets).
3. **Diphthong split (LIP-04, docs/EN-visemes.md §5.5 "option 2 for AY and AW")**:
   - In `phoneme-visemes.ts` export `DIPHTHONG_END_POSES: Record<string, string>` mapping
     `'AY' → 'IH'`, `'AW' → 'UH'` (the end-glide poses per the doc: AY ends [ɪ], AW ends [ʊ]).
   - In `phoneme-merge.ts`, when emitting spans, if `phoneme === 'AY' || phoneme === 'AW'`,
     emit **two spans**: first the diphthong's own pose over the first 60% of its allotted
     time, then the end pose (`IH`/`UH`) over the remaining 40% (both renormalized inside
     the word window per task 1 — the pair is just two spans with the weights folded in).
     Implementation detail: do this inside the per-word duration distribution so the
     word-sum invariant from task 1 still holds (distribute the diphthong's weight across
     its two child spans).
   - EY/OW/OY stay single static poses (doc: "reszta statycznie").
   - Tests: "my" (AY) → spans include AY then IH; "how" (AW) → AW then UH; sum invariant
     still exact; "go"/"day"/"boy" unchanged (single span).
4. **Table as single source of truth + effective-value layering (LIP-04)**:
   - In `phoneme-visemes.ts`, export the pose table as a typed const
     `PHONEME_POSES: Readonly<Record<string, LipPose>>` consumed by `mapPhonemeToShapes`
     (same values, no behavior change) — so `testPhoneme` and future tools can read it.
   - Add a module-doc block stating the layering explicitly: *effective = table value ×
     profile scale (`scaleForShape`) × safety cap (`CLOSE_SAFETY_CAP = 0.85` for close).
     Bilabial closure (M/B/P) is PERCEIVED closure, not mouthClose alone: since 11.2 SHOW-06
     the pose is jawOpen ≈ 0 + mouthPress + mouthRollUpper/Lower with mouthClose kept low on
     purpose (high mouthClose pulls the lower lip onto the nose on MetaPerson, docs/EN-visemes.md
     §3 MBP note).* (amended 2026-11-19 — the old "≈ 0.51" was miscomputed: 0.8 × 0.6 = 0.48.)
   - **Computed perceived-closure test** (tests/phoneme-visemes.test.ts, replaces the current
     hardcoded `mouthClose === 0.8` assertion semantics): for `M/B/P` under the balanced

     (do not hardcode the old `close: 0.8`). This replaces LIPS-06/LIP-04's "≥ 0.85 effective
     mouthClose" wording — record that change in the SUMMARY and the 17-06 docs diff list.

## Risks & mitigations

- **Diphthong split changes the feel of live speech** (2 queue items where 1 was) →
  scheduler additive blending softens it by design; the split is per doc recommendation,
  gated behind the UAT harness (17-05) for a live A/B — revert is a 2-line constant change
  (drop AY/AW from the split map).
- **Span-sum invariant may reveal the 35 ms floor is too aggressive for fast speech**
  (words genuinely spoken faster than 35 ms/phoneme) → the fix renormalizes rather than
  clamps, so no viseme is lost; MIN_SPAN_MS becomes a *soft* minimum inside the word —
  if UAT shows mushy consonants, tune the floor down (single constant, tested).
- **testPhoneme delegation subtly changes Calibrator behavior** (multiplied values were
  hand-tuned, not pure table reads) → keep the multiplier semantics identical
  (`value × profile.scale`), visual dev check before merge; if a pose regresses visually,
  record and defer that key's delegation to the harness verdict rather than blocking.
- **Phase 16 parallel edits to face-controller.ts** (G-6 guard, state matrix) → sequence
  after 16-01 or re-anchor; this plan touches ONLY the testPhoneme method body.
