# 17-04: PL rule-based G2P — the phoneme path for Polish

## Goal

Replace the crude 1-char-window char table as the PRIMARY PL path with a deterministic
rule-based PL G2P (§A.7): Polish orthography is nearly phonemic, so rules-only beats the
char table and needs no lexicon — while the char table survives as the ultimate PL fallback.

## Requirements

LIP-05.

## Files

- `src/lipsync/g2p/g2p-pl.ts` (new ~150 lines) — PL rules engine
- `src/lipsync/g2p/phoneme-merge.ts` (language-aware word→phonemes dispatch)
- `src/lipsync/g2p/phoneme-visemes.ts` (PL phoneme-class → pose entries; reuse `pose()`)
- `src/lipsync/viseme-mappings.ts` (fix `ch` for PL; keep as fallback path)
- `src/lipsync/face-controller.ts` (branch selection per language source)
- `src/app/store/settings-schema.ts` (engine setting becomes per-language: `en`/`pl`/`char`)
- `tests/g2p-pl.test.ts` (new), `tests/viseme-mappings.test.ts` (extend T-6 pins)

## Tasks

1. **`g2p-pl.ts` rules engine** (structure mirrors g2p-en's `rulesFallback`; ordered,
   left-to-right, longest-match-first):
   - Digraphs: `sz`→SZ, `cz`→CZ, `rz`→RZ(≈ż), `ch`→H(velar [x] — NOT the EN CH pose),
     `dz`→DZ, `dź`→DŹ_SOFT, `dzi`→DŹ_SOFT (consumes the i), `ci`→Ć_SOFT, `ni`→Ń_SOFT,
     `si`→Ś_SOFT, `zi`→Ź_SOFT — softness-i consumed into the preceding consonant ONLY
     when followed by a vowel (the §A.7 fix: "zima" stays [z+i], "ziarno" becomes [ʑ-…]).
   - Single diacritics: ą/ę → nasal vowel classes A~/E~; ó→U; ł→W-like (dark L ≈ W pose);
     ś/ć/ź/ż → soft classes (map to the same poses as EN SH/CH/ZH family via the pl map).
   - **Final devoicing** (b→p, d→t, w→f, z→s, ź→ś, ż→sz, dź→ć at word end) — one pass after
     tokenization; cheap and very visible in speech ("chleb" → [xlep]).
   - Output: PL phoneme-class tokens (the §A.7 13-class set reusing EN pose classes where
     they coincide: p/b/m, f/v, s/z, sz/ż/rz, cz, dz/dź, t/d/n, k/g, ch/h, l, r, j, ł,
     vowels a/e/i/o/u/y + nasals) — NOT IPA; viseme classes suffice (documented contract).
2. **Merge dispatch** (`phoneme-merge.ts`): word run → language check (contains PL
   diacritics OR produces a PL digraph hit → `g2pPl`; else `g2pEn`) → same
   `PhonemeSpan[]` output (weights: PL vowels 1.2/consonants 0.8 identical). Mixed
   words in one turn are handled per-word (that's the documented limit; mixed-language
   TURNS auto-detection is explicitly deferred, §A.7).
3. **Pose table extension** (`phoneme-visemes.ts`): `PL_PHONEME_POSES` mapping the PL
   classes → poses (reuse EN entries by class; new entries only for ł (W pose), nasals
   (open + slight funnel), H (open, no smile)).
4. **Char-table fixes** (fallback path quality, T-6 pins first): `ch` in PL context →
   H-class pose (the mapping table gains a PL-context entry — the EN `ch` stays for EN
   turns; language context flows the same way as task 2); keep everything else.
5. **Settings** (`settings-schema.ts`): `lipSyncEngine` extends to
   `'phoneme-en' | 'phoneme-pl' | 'char'` with migration from the old boolean/enum value
   (legacy `phoneme` → `phoneme-en`); studio Animation panel label updates (coordinate:
   if Phase 15 landed, the label comes from copy.ts slot `animation.engineLabel`).
6. **Tests** (`tests/g2p-pl.test.ts`): the §A.7 control set — `szczypczyzna`,
   `dziękuję` (DŹ_SOFT + …, no separate DZ+I), `chata` (H not CH-church), `ziarno`
   (Ź_SOFT), `zima` (plain Z+I), `trzeba` (RZ), `chleb` (final devoicing → ends P pose),
   nasal sentences (`kąt`, `węże`); plus merge integration: PL word timing anchors the
   same way as EN (span-sum ≈ word window). `viseme-mappings.test.ts`: T-6 pins for the
   fixed `ch` behavior in both language contexts.

## Acceptance criteria

- [ ] All g2p-pl control-sentence tests green; zero model needed
- [ ] `dziękuje`/`chata`/`zima` produce the corrected sequences (no EN-church `ch`, no
      false softness on `zi` in "zima")
- [ ] `npm test` green (incl. all prior phases' suites); `npm run build` green
- [ ] Studio A/B: PL sentence on phoneme-pl vs char path — both play, phoneme path visibly
      sharper on digraphs (manual, feeds 17-05 UAT)
- [ ] Settings migration: old persisted value loads without error (test in
      settings-store suite)

## Test/verification strategy

Unit tests are the core (deterministic rules); migration test; manual A/B deferred to the
17-05 UAT protocol (PL section).

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| Rule interaction bugs (softness-i vs vowel-i) | Longest-match-first + the 6 control sentences pin exactly the ambiguous cases |
| Schema migration breaks persisted profiles | Migration is a pure enum remap; store test covers legacy→new |
| Overlap with Phase 15's copy slots | Engine label flows through copy.ts if present; fallback to literal otherwise (task 5 note) |
