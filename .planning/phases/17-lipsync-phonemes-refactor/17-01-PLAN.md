# 17-01: CMU decision execution — measure, prune, and harden the EN lexicon path

## Goal

Execute the CMU dictionary decision from 17-CONTEXT §A.5 (Option B+e: build-time pruned
lexicon + hardened OOV rules) and close the OOV quality gaps (§A.3): the 961 kB gzip chunk
and ~286 ms main-thread parse disappear from the browser payload, replaced by a measured,
committed artifact — while the degradation ladder and all existing behavior for
lexicon words stays intact.

## Requirements

- LIP-01 (pruned lexicon, build script, fallback ladder, measured gate)
- LIP-02 (OOV silent-letter + -tion rules, pinned by tests)

## Files

- `scripts/build-dict-en.mjs` (new) — pruning script (Node, no deps)
- `scripts/lipsync-corpus.mjs` (new) — shared corpus list used by both the prune script and tests
- `src/lipsync/g2p/dict-en-pruned.json` (new, committed artifact)
- `src/lipsync/g2p/g2p-en.ts` (modify — loader + rules)
- `tests/g2p-en.test.ts` (modify — extend)
- `tests/fixtures/oov-wordlist.json` (new)
- `package.json` (add `build:dict` script)

## Tasks

1. **Create `scripts/lipsync-corpus.mjs`** exporting `CORPUS_SENTENCES: string[]` —
   (a) the 7 control sentences from docs/EN-visemes.md §6 verbatim, (b) ~10 conversational
   agent sentences (tech talk, small talk, apologies, questions), (c) ~6 sentences stressing
   OOV territory (technical loanwords, rare words). Export `CORPUS_TOKENS` (lowercased word
   tokens). This module is the single source of truth for both the prune measurement and the
   golden-span tests (17-03).
2. **Create `scripts/build-dict-en.mjs`**: reads the full `cmu-pronouncing-dictionary`
   (devDependency stays), selects the top-N most frequent word forms measured as:
   `frequency = count in CORPUS_TOKENS` (corpus words always included) `+ 1` for every word
   in a wordlist derived from dictionary key ordering for base coverage — concretely:
   include (i) all corpus tokens, (ii) all words of length ≤ 2 (273 keys — function words),
   (iii) dictionary keys in alphabetical order until N entries total. **Measurement step
   (must run and record output in the plan SUMMARY): for N ∈ {5k, 10k, 20k, 50k, full},
   print hit-rate on CORPUS_TOKENS, raw size, gzip size (level 9) of the JSON artifact.**
   Write the chosen N to the artifact as `{"meta": {"generated": "<date>", "source": "cmu-pronouncing-dictionary@3", "entries": N}, "entries": {word: "PHONEMES WITH STRESS"}}`.
   Decision gate written in the script's header: pick the smallest N with ≥95% hit-rate;
   expected 10,000 (predicted gzip ~70-80 kB); if <95% at 10k, use 20,000 (~138 kB). The
   script must be deterministic and idempotent (sorted keys) so re-running is byte-identical.
3. **Add `npm run build:dict` to package.json** (`node scripts/build-dict-en.mjs`). The
   artifact is committed; the script is for regeneration only. Add a comment in the script
   header documenting when to re-run (vocabulary drift complaints, CMUdict upgrade).
4. **Rewire `g2p-en.ts` loader**: `ensureG2pLoaded()` lazy-imports the committed JSON
   (`import('./dict-en-pruned.json')` — Vite still code-splits it, now a ~10× smaller chunk),
   strips stress digits in `buildTable` exactly as today (g2p-en.ts:24-31). Keep the
   module-level API surface identical: `ensureG2pLoaded`, `isG2pReady`, `g2pAvailable`,
   `wordToPhonemesSync` — no caller changes (face-controller.ts:5,86 untouched).
   `cmu-pronouncing-dictionary` moves from `dependencies` to `devDependencies` (verify build
   still passes with `npm run build`).
5. **Harden `rulesFallback` in g2p-en.ts** (the function at g2p-en.ts:70-194):
   - Add an ordered **exception list** checked before the letter loop for word-internal
     silences: `island`→IH-S-L-AH-N-D (drop S), `listen`→L-IH-S-AH-N (drop T), plus the
     productive classes `-sten` (listen/glisten), `-stle` (castle/whistle), `-ceipt`
     (receipt/deceit — P silent), `hour/honest/heir` (initial H silent), `sandwich`,
     `Wednesday`. Keep the list as a `const OOV_EXCEPTIONS: Record<string, string[]>` plus
     two suffix rules (`-sten`, `-stle`) applied before the main loop.
   - Add a **`TION`/`SION` rule**: at the end of a word (or before final S), `tion` →
     `['SH','AH','N']`, `sion` → `['ZH','AH','N']` (VO-versions stay when preceded by a vowel,
     else `SH`). Insert before the generic letter loop (after digraph handling).
   - Do NOT touch existing correct rules (KN/WR/MB/GH/magic-E, digraphs). All current
     g2p-en.test.ts assertions must keep passing unchanged.
   - **Fix the `-ed` rule (amended 2026-11-19 — refactoring.md R2 B9).** It is NOT correct:
     `g2p-en.ts:93-97` does `i += 2` and emits nothing, dropping both the vowel and the D (OOV
     "xanted" → K S AE N T). Replace with: after a stem ending in `t`/`d` → `IH D`; after a
     voiceless stem consonant (p, k, f, s, sh, ch, x) → `T`; otherwise → `D`. Only OOV words reach
     this rule (CMU covers wanted/played/jumped). Tests: OOV fixtures `blanted` → ends `IH D`,
     `flomped` → ends `T`, `zarbed` → ends `D`.
   - **Digraph second-letter skip in the char engine (amended 2026-11-19 — R2 B8).**
     `viseme-mappings.ts:286-291` maps a digraph (th/sh/ch/…) on its first letter, but the caller
     loop in `face-controller.ts:338-363` still enqueues the second letter as its own shape (e.g. an
     extra H pulse). After a matched digraph, skip index+1 in that loop and in the `charTokenFor`
     override path. Only the 'char' engine and the G2P-loading fallback use this loop. Test: chunk
     "the" → exactly 2 enqueued visemes (TH, E), not 3. If `face-controller.ts` is mid-refactor by
     Phase 16, re-anchor by grep `mapSingleChar`/`charTokenFor`.
6. **Extend `tests/g2p-en.test.ts`**:
   - New describe "OOV exception coverage (LIP-02)" reading `tests/fixtures/oov-wordlist.json`
     (committed list of `{word: string, expect: string[]}` pairs — include island, listen,
     castle, receipt, Wednesday, question (lexicon), automation (OOV -tion), mission,
     honest, hour) asserting `wordToPhonemesSync` output *phoneme sequences* (for lexicon
     words: unchanged lexicon results — regression pin).
   - New test: corpus hit-rate — import CORPUS_TOKENS from the corpus script, assert ≥95%
     of tokens resolve via the pruned lexicon directly (`wordToPhonemesSync` non-null with
     lexicon-loaded table, before rules fallback; distinguish by temporarily calling the
     internal lookup or by asserting `isG2pReady()` and using a `lookupOnly` export added
     for tests). Simplest: export `wordInLexicon(word): boolean` from g2p-en.ts (used by
     tests and by the future telemetry).
   - New test: pruned-artifact integrity — `dict-en-pruned.json` parses, has `meta.entries`
     ≥ 5000, and every corpus token of length ≥ 3 is either present or known-OOV (from the
     fixture list) — protects against regenerating the artifact without the corpus step.
7. **Record the measurement** (task 2 output: hit-rates + sizes table) in
   `17-01-SUMMARY.md` — this is the evidence closing the STATE.md blocker
   ("Open decision: dictionary pruning").

## Test/verification strategy

- Existing backstop: g2p-en.test.ts (lexicon mappings, stress stripping, OOV non-null),
  phoneme-merge.test.ts + face-controller tests consume the same loader — they catch any
  loader-shape regression.
- New: oov-wordlist fixture tests, corpus hit-rate test, artifact integrity test, dist-size
  check (manual step documented in SUMMARY; candidate for CI in phase 18 — cross-note).
- Verification: run `npm run build` and list `dist/assets/*.js` sizes before/after — the
  3.92 MB chunk must be gone.

## Risks & mitigations

- **Pruned lexicon misses a word mid-conversation** → degrades to letter rules (visually
  still plausible for rare words) and never to nothing; wordInLexicon lets the studio
  telemetry surface it later. Regenerate with a bigger N is a one-command re-run.
- **JSON import chunking differs between Vite versions** → verify the dist chunk exists and
  is lazy (network waterfall shows it loading after first render, not before); if a Vite
  change inlines it, fall back to a `.ts` artifact (`export const dictionary = {...}` —
  identical pruning script with a different serializer; script already parameterized).
- **OOV exception list becomes a maintenance magnet** → capped list (documented in code);
  additions require a fixture entry — the test IS the review gate.
- **Measurement skew**: corpus is self-authored (circularity) → mitigated by including
  alphabetical-fill base coverage + the 273 short-function-word set; the gate is corpus
  hit-rate, not realism — documented as such.
